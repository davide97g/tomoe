# Task: design and animate "Copy", the mascot cat of Tomoe

Tomoe is a chat app that designs dashboards and widgets. Its UI is being redesigned in the style of
`reference.png` (attached, also in this folder): monochrome, warm paper background, Bauhaus-simple,
flat illustration with thin dark outlines, Japanese concept-sheet feel. The mascot is a cat called
**Copy**. It will live in the UI and react to app states (idle, thinking/loading, success, error,
walking around the page, sleeping when nothing happens).

Use your image generation tool for every drawing. Use the Python venv at `.venv/bin/python`
(Pillow, numpy, scipy already installed; no network) and `ffmpeg` for processing. Work only inside
this folder.

## 1. Character design

Style must match the cats in `reference.png` (the "CAT STATE" row and the flying cat): chubby round
body, white fur with a few black patches, black ears, black tail tip, tiny dot eyes, tiny nose,
small blush-free face, thin near-black outline (#111111), flat fills, at most a soft warm-gray
shadow under the belly. Palette strictly from: #111111 #333333 #777777 #BEB8AD #E6E1D7 #F6F4EE
(plus pure white for fur highlights if needed). No other colours, no gradients, no text.

Give Copy one distinctive detail that makes it ownable (e.g. a black patch shaped like a small
square/page over one eye, a nod to "copy"), and keep it identical in every image.

Produce `design/copy-sheet.png`: a model sheet (front, 3/4, side, back, a few expressions) on the
#F6F4EE paper background. This is the canonical design; every later frame must be on-model with it.

## 2. Animations (frame by frame)

Make these loops, side view facing right unless noted, same scale and same ground line in all:

| name     | frames | fps | what                                                                 |
| -------- | ------ | --- | -------------------------------------------------------------------- |
| idle     | 8      | 8   | sitting, gentle breathing, tail sway, one blink                      |
| walk     | 8      | 10  | full walk cycle in place (the page moves the cat, not the frames)    |
| think    | 8      | 8   | loading: sitting, looking up, tail flicking, paw tapping, "..." feel |
| success  | 8      | 10  | happy hop with a little stretch, lands back in the idle pose          |
| error    | 6      | 8   | ears flatten, small flinch, sheepish look, back to neutral           |
| sleep    | 6      | 5   | curled loaf, slow breathing, ear twitch                              |
| jump     | 8      | 12  | crouch, leap (like the reference flying cat), land                   |

For consistency, generate each animation as ONE image containing all its frames in a single row
(sprite sheet) on a perfectly flat solid #00FF00 background, character fully inside each cell,
cells evenly spaced, no overlap, no shadows touching cell borders. Keep green out of the character.
Pass `design/copy-sheet.png` as the reference when generating. If a sheet comes out off-model,
inconsistent in size, or the motion is not smooth, regenerate it (or regenerate single frames
with the sheet as reference). Look at every result yourself before accepting it.

## 3. Processing (script it: `tools/process.py`, rerunnable)

For each sheet:
- Key out the green (with edge despill so no green fringe), keep crisp anti-aliased outlines.
- Split frames (connected components / column gaps, not blind equal slicing).
- Align: same scale for every frame of every animation (use the idle body height as the unit),
  feet on one shared baseline, horizontal anchor at the body centre so the cat does not jitter.
  Smooth any residual jitter of the anchor across the loop.
- Export `frames/<name>/NN.png` (transparent, same canvas size for all, e.g. 320x320) and
  `sprites/<name>.png` (horizontal strip of those cells) plus `sprites/<name>.webp` (animated,
  transparent, at the listed fps) and `sprites/manifest.json`
  (`{ name: { frames, fps, cellWidth, cellHeight, loop } }`).
- Check the loop: last frame to first frame must flow. Fix or regenerate if it pops.

## 4. Preview page `preview/index.html` (static, no build, opens from file://)

On #F6F4EE paper, in the reference's concept-sheet layout (thin tracked uppercase labels, thin
rules): every animation playing from its sprite strip with CSS `steps()` or a tiny JS player,
each with play/pause, fps slider, step frame, onion-skin toggle and a frame strip under it.
Plus a "stage" at the bottom where Copy walks across the page, stops, idles, falls asleep after a
while, and reacts to buttons: think, success, error, jump (state machine, flips horizontally when
turning around). Smooth: use requestAnimationFrame for movement, image swaps for frames, preload
everything.
