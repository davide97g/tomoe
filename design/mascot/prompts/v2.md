# Task: v2 of Copy's animations: perfectly smooth, rigged from parts, baked to frames

Read `NOTES.md`, `PROMPT.md`, look at `design/copy-sheet.png` and `v1/contact.png` (v1 frames side by
side; the last cell of each row is an onion-skin overlay of all its frames). v1 is saved in `v1/`.

## Why v1 is not good enough

Every frame was redrawn by the image model, so the cat wobbles:
- scale differs between animations (error and sleep ~30% bigger than idle) and some cells clip
  the cat (error, think, sleep);
- walk barely moves and jitters sideways; jump has no clean arc;
- off-model frames: error frame 4 (patch and ears move), success frame 6 (stray marks);
- think/walk have a grainy fur texture, idle has flat fills.

The design itself is approved: keep Copy exactly as in `design/copy-sheet.png` (round white body,
black ears and patches, black tail tip, square black "page" patch over the eye, thin #111111
outline, flat fills, the 3/4 right-facing view v1 used).

## v2 approach: cut-out rig, baked to frames

1. **Parts.** Use image generation (with `design/copy-sheet.png` as reference) to make ONE clean,
   high-resolution canonical pose (3/4 view, facing right, sitting/standing like v1 idle) on a flat
   green key, flat fills only. Then produce separate layers for that exact pose: body (with
   patches), head (if it can be separated cleanly; else head+body as one), left ear, right ear,
   tail, four paws/feet stubs, and face variants drawn on the same face area: neutral, blink
   (closed), happy (^ ^ / smile), sad/sheepish (ears-back look, small mouth), sleeping (closed
   curved eyes), looking-up. Plus one curled "loaf" body for sleep with its own ear/tail parts.
   Parts must line up pixel-perfectly when composited back (verify by recompositing and
   diffing against the canonical pose). You may cut parts out of the canonical pose with masks and
   repaint the hidden areas, or generate them separately and fit them; whatever gives clean edges.
   Keep everything flat-filled and inside the palette (#111111 #333333 #777777 #BEB8AD #E6E1D7
   #F6F4EE + white).
2. **Rig.** `tools/rig.py`: a small skeleton (pivots for body, head, each ear, tail base, each
   paw), transforms per part (translate, rotate around pivot, scale for squash/stretch), drawn in
   a fixed order. Render at 2x and downsample for clean anti-aliasing. Animate with eased curves
   (sine for loops, ease-in/out and overshoot for one-shots), not linear steps.
3. **Animations**, all at **24 fps**, same scale, same ground line, same canvas (320x320 cells,
   enough headroom so jump never clips), loops seamless (frame N flows into frame 1):

   | name    | length | motion                                                                                   |
   | ------- | ------ | ---------------------------------------------------------------------------------------- |
   | idle    | ~3 s   | breathing (1-2% squash/stretch), slow tail sway, ear flick once, one blink               |
   | walk    | ~1 s   | 4-paw walk cycle (diagonal pairs), body bob twice per cycle, slight head counter-bob, tail sway; in place |
   | think   | ~2 s   | looking-up face, head tilt, tail tip flicks, front paw taps twice                         |
   | success | ~1.2 s | anticipation squash, hop with stretch, happy face, squash on landing, settle to idle pose |
   | error   | ~1 s   | ears flatten back, small flinch/shake, sad face, recover to neutral                      |
   | sleep   | ~4 s   | loaf pose, slow deep breathing, one ear twitch                                           |
   | jump    | ~1.2 s | crouch, launch with stretch, parabolic arc (height ~0.6 body), tuck, land with squash, settle |

   One-shots (success, error, jump) must start and end exactly on the idle rest pose so the app
   can chain them; mark them `loop: false` in the manifest.
4. **Export** like v1 (overwrite top-level outputs): `frames/<name>/NNN.png`, `sprites/<name>.png`
   strips (if a strip gets too wide for browsers, >16000 px, wrap into a grid and record
   `columns` in the manifest), `sprites/<name>.webp`, `sprites/manifest.json`
   (`{ name: { frames, fps, cellWidth, cellHeight, columns, loop } }`). Also save the parts and
   `rig/rig.json` (pivots, draw order, keyframes) so frames can be rebaked.
5. **Verify with numbers, not just eyes.** Write `tools/check.py`: per animation, the bounding box
   and alpha centroid per frame, plus the max per-frame jump of the anchor for loops (should be
   smooth, no spikes), cat height relative to idle (must be 1.0 at rest), no alpha touching cell
   borders, first/last frame difference for loops. Make a new `contact.png` (frames sampled every
   3rd, plus onion-skin) and look at it. Iterate until it is right.
6. **Preview**: update `preview/index.html` for the new manifest (24 fps, grid strips, loop flag;
   one-shots replay on click and return to idle). Add a v1/v2 toggle so both can be compared
   (v1 assets are in `v1/`). The stage state machine chains one-shots back to idle/walk.

Use `.venv/bin/python` (Pillow, numpy, scipy) and ffmpeg. Work only in this folder.
Update `NOTES.md` with a v2 section. Final message: files, what the checks report, any flaws left.
